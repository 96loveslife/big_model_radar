## 2. CLI 工具进展

### 2.1 总体格局

本周八款 CLI 的演进可归纳为五个方向：

- **从单会话助手转向 Agent 平台**：后台任务、子代理、MCP、Skills、ACP、Desktop 和 Remote Control 成为主线。
- **从功能可用转向生命周期可信**：会话恢复、取消、终止原因、状态持久化和事件可观测性受到持续关注。
- **权限从粗粒度开关转向细粒度治理**：只读操作、Shell、Browser Use、Git 写操作、Hook 和企业策略需要统一、可解释的权限模型。
- **上下文管理从压缩功能转向成本与正确性治理**：压缩失败、重复请求、重复计费、工具记录丢失和模型目录漂移成为高频问题。
- **多 Provider 扩张带来配置一致性问题**：静态模型目录、Provider 不可见、会话恢复后模型变化，以及扩展 API 兼容成为共同痛点。

### 2.3 值得特别关注的工程共识

1. **“成功”必须成为可信状态，而不是默认返回值。**  
   子代理达到轮次上限、预算耗尽、用户取消、权限阻断和进程异常，均应映射为明确终止原因，并沿父任务正确传播。

2. **权限策略必须覆盖所有执行入口。**  
   File Tool、Shell、Browser Use、Hook、Git 和 MCP 工具不能各自维护互不一致的放行规则；只读操作应有更低摩擦的安全执行路径。

3. **升级后的状态恢复应优先于新增能力。**  
   本周多次出现配置、模型、索引、会话和子进程在升级或重启后丢失的问题，说明迁移机制已经成为生产可用性的关键路径。

4. **上下文压缩必须兼顾语义正确性与成本。**  
   压缩失败后整轮重放，可能同时造成重复执行、重复计费和状态污染；应建立压缩指纹、幂等键与执行去重机制。

### 本周结论

- 明确的执行结果与终止原因；
- 统一的权限决策和审计记录；
- 可恢复的会话与后台任务；
- 幂等的工具调用和上下文压缩；
- 动态一致的 Provider 与配置模型；
- 跨终端、跨协议的状态连续性。

这些能力将决定 AI CLI 能否从优秀的开发助手进一步成为可被团队和自动化系统长期信任的 Agent 基础设施。
