## 五、功能需求趋势

  Harness 把人类消息意外串入子代理，是多代理编程体验中最隐蔽的一类 Bug，开发者希望官方提供更明确的"harness 上下文契约"文档与可观测性接口。

## 6. 开发者关注点

从反馈中归纳的高频痛点与诉求：

1. **Provider 一致性**：OpenRouter 成本失真、Copilot 模型缺失、Meta OAuth UA、Anthropic 流异常 —— 反映出多 provider 适配的维护负担明显加重，需要更系统化的 catalog 同步与适配测试。

2. **长会话可扩展性**：嵌入到长期运行服务（OAR、ARF）时，内存只增不减、resume 加载整文件等问题（[#10642](https://github.com/earendil-works/pi/issues/10642)、[#10629](https://github.com/earendil-works/pi/issues/10629)）已经成为生产化部署的障碍。

3. **扩展 API 的边界**：`VIRTUAL_MODULES` / `HOST_PROVIDED_EXTENSION_PACKAGES` 漏配、MCP 资源注册时序、editor border widget 缺失、footer hook 过于刚性等都在推动**扩展 API 的进一步暴露**。

4. **重试与限流合规**：agent-level retry 忽略 `Retry-After`（PR [#10600](https://github.com/earendil-works/pi/pull/10600)）意味着与 429 等限流协议握手不够"礼貌"，未来需要更完善的退避策略。

5. **TUI 鼠标与文本交互**：fullscreen 模式下中键事件、链接可点击性、复制尾随空格、bash 工具长时间 elapsed 显示（[#9628](https://github.com/earendil-works/pi/issues/9628)）等小细节显著影响日常使用体验。

6. **计费准确性**：`before_agent_start` 注入的 system prompt 在非 user-driven run 中被丢弃并重复计费（[#10267](https://github.com/earendil-works/pi/issues/10267)），提示**计费模型与扩展机制的耦合需要更精细的合约**。
